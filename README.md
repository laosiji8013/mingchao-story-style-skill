# 《明朝那些事儿》文风切片蒸馏 Skill

这是一个从《明朝那些事儿》全书文风中提取、切片并蒸馏而成，可直接安装使用的中文写作 Skill。它把其中可迁移的结构、节奏、白话解释和故事推进方法整理成可执行规则，用于把复杂材料改写成事实优先、短段落推进、讲人话、轻幽默、有故事感的原创中文内容。

**它不是“模仿某位作者”的提示词，也不是给模型套上一段系统提示词。**

它来自对《明朝那些事儿》完整长篇文本进行连续切片、统计标注、功能分类和规律提取，再经过重复性筛选、跨主题迁移测试和边界测试后形成的写作方法 Skill。也就是说，成品靠的是蒸馏后的结构、节奏、解释方法和质量闸门，不需要在每次使用时把原书放进上下文。

公开仓库只保留聚合统计、写作规则和原创示例，不包含书籍原文、长段摘录或可重建原文的切片内容。

> 这个 Skill 提炼的是结构、节奏、解释方法和质量检查，不冒充作者本人，也不承诺逐句复刻任何在世作者的独特表达。

## 能做什么

- 把专业概念讲给普通读者听；
- 把产品、AI、流程、商业案例写成有推进感的故事；
- 把生硬、报告式、术语密集的中文改得清楚好读；
- 写人物小传、事件复盘、产品解释和科普文章；
- 检查草稿是否空泛、营销化、过度玩梗或脱离事实；
- 作为其他 Agent 的可复用中文写作能力。

不适合直接用于法律文本、正式公文、学术论文或需要逐条证据链的研究报告。

## 它不是什么

- 不是“你现在就是某位作者”的角色扮演提示词；
- 不是复制固定句式、口头禅和名句的仿写模板；
- 不是把书籍原文藏进系统提示词后再生成；
- 不是每次运行都要检索原书的 RAG 知识库；
- 不是对原作的续写器或替代品。

它是一套从完整文本证据中提炼出的、可以迁移到 AI、产品、流程、人物和科普写作中的方法规则。

## 一分钟安装

### Codex / 通用 Agent

```bash
git clone https://github.com/laosiji8013/mingchao-story-style-skill.git
cd mingchao-story-style-skill
python3 scripts/install_skill.py
```

Windows PowerShell 使用 `py scripts/install_skill.py`。

默认安装到 `~/.codex/skills/mingchao-story-style`。如需安装到其他 Agent 的 Skills 目录：

```bash
python3 scripts/install_skill.py --target /path/to/skills
```

安装器发现同名目录时会停止，不会覆盖你已有的 Skill。

重启或重新加载 Agent 后，使用：

```text
使用 $mingchao-story-style，把下面材料改写成普通人愿意读的故事化中文。
读者：小企业经营者
用途：公众号文章
必须保留的事实：……
禁止出现：夸大效果、虚构数据
长度：1200 字左右
材料：……
```

### 直接复制 Skill

仓库中的成品目录是：

```text
mingchao-story-style/

```

把整个目录复制到你所使用 Agent 的 Skills 目录即可。不同产品的 Skills 路径可能不同，以该产品说明为准。

## 最小输入

为了避免写得像套话，最好提供六项信息：

```text
主题：要写什么
读者：写给谁
事实：哪些内容必须准确保留
用途：公众号、讲稿、产品说明还是人物小传
禁区：不能出现什么判断、数据或说法
长度：大约多少字，是否需要标题和小标题
```

资料不足时，Skill 会明确指出缺口，不用故事感掩盖事实空白。

## 输出特点

默认使用这条主线：

```text
事实锚点 → 明确判断 → 具体场景 → 压力或冲突 → 转折 → 白话解释 → 边界 → 收束
```

写作时通常表现为：

- 先告诉读者什么最重要；
- 一段只放一个主要意思；
- 让人物、事件或问题在压力中推进；
- 把术语翻译成日常语言；
- 用转折改变读者预期，但不制造假戏剧；
- 幽默只负责缓压，不负责证明观点；
- 最后落到结论、边界或下一步。

## 使用示例

### 解释概念

```text
使用 $mingchao-story-style，向非技术读者解释“大模型上下文窗口”。
必须说明：它是一次能处理的材料范围，不等于永久记忆。
长度：600 字。
```

### 改写产品材料

```text
使用 $mingchao-story-style 改写下面的 AI 产品介绍。
删除营销套话，先讲使用场景，再讲能力、限制和适合人群。
禁止补写材料中没有的数据。
材料：……
```

### 写人物小传

```text
使用 $mingchao-story-style，根据以下事实写人物小传。
按“出身/位置—目标—限制—选择—后果”推进。
不要虚构心理活动，不要复刻书中句式。
事实材料：……
```

### 检查已有草稿

```text
使用 $mingchao-story-style 检查下面草稿。
列出：事实缺口、报告腔、营销腔、长段落、无效玩笑和结尾问题；
然后给出修订版。
草稿：……
```

## 蒸馏过程

公开版的方法过程如下。这里的“蒸馏”指从全量文本证据中提取可重复机制，不是把一段提示词换个名字：

1. 将长篇材料切分为连续功能片段；
2. 只记录位置、长度、段落、句子、功能标签和语言标记计数；
3. 从结构、语气、句法、白话解释、人物和故事推进六个方向提出候选规则；
4. 只保留重复出现、能迁移到新主题、又不是固定口癖的规则；
5. 把规则写成“现象—解释—动作—边界”的可执行单元；
6. 使用 AI、产品、流程、人物和边界任务进行原创测试；
7. 删除依赖原文、依赖作者身份或容易导致仿写过近的规则。

原始分析覆盖完整长篇文本，并生成 1831 个连续元数据切片。为避免发布可重建的定位信息，仓库只公开聚合统计和蒸馏方法，不公开书籍文本与逐切片定位表。

Skill 运行时读取的是蒸馏成果，不是原书：

```text
完整文本（仅分析阶段）
        ↓
连续切片与功能标注
        ↓
聚合统计和候选规律
        ↓
重复性 / 可迁移性 / 非口癖性筛选
        ↓
原创跨主题测试与边界测试
        ↓
可直接安装的 Skill 规则
```

## 质量标准

成品应同时满足：

- 事实没有被故事感覆盖；
- 重要术语得到白话解释；
- 大部分段落短而有推进；
- 判断能由材料支撑；
- 转折服务于理解，不是硬造戏剧；
- 幽默不过量、不冒犯、不抢重点；
- 结尾回答“所以呢”；
- 没有冒充作者、复制原文或套用固定口癖。

## 版权与边界

- 仓库不包含《明朝那些事儿》正文或长段摘录；
- 所有公开示例均为新写的通用示例；
- 书名仅用于说明研究灵感和用户常用检索方式；
- Skill 不应声称生成结果就是原作者作品；
- 用户提供短摘录用于分析时，也应只分析机制并生成原创内容；
- 事实准确性仍取决于用户提供的材料和最终复核。
