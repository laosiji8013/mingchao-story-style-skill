# 结构模式

## 默认文章结构

1. 事实锚点：先说具体对象或事件。
2. 判断：告诉读者真正重要的是什么。
3. 场景：让问题在真实使用环境中出现。
4. 压力：解释为什么事情会变难。
5. 转折：揭示误区、限制或隐藏条件。
6. 解释：把机制翻译成普通中文。
7. 边界：说明它不能解决什么。
8. 收束：回答“所以呢”。

## 开头

### 结果先行

适合有反常识结果的主题：

```text
这件事真正改变的，不是 X，而是 Y。
```

### 问题先行

适合读者已经有痛点的主题：

```text
问题不是没人知道要做，而是每个人理解的“做好”都不一样。
```

### 术语翻译

适合技术概念：

```text
这个词听起来很硬，说的其实是一件很普通的事。
```

以上只是功能模式。生成时应根据事实改写，不要机械套句。

## 推进

使用阶梯式段落：

```text
事实出现。
问题变大。
人物或工具做出选择。
限制暴露。
原因浮出来。
结论落下。
```

转折词承担不同任务：

| 任务 | 可选词族 |
| --- | --- |
| 时间推进 | 于是、后来、终于、从此 |
| 改变预期 | 然而、不过、可是、但是 |
| 白话解释 | 其实、换句话说、也就是说 |
| 暴露问题 | 问题是、麻烦在这里、真正难的是 |
| 局部收束 | 所以、到这里、这就说明 |

变化的是功能，不只是换同义词。不要为了像某种文风而高频重复固定转折。

## 结尾

好结尾应完成至少一项：

- 回答开头的判断；
- 说明发生了什么变化；
- 给出边界或代价；
- 让读者知道下一步该做什么。

避免用口号、突然煽情或名言引用代替结论。
