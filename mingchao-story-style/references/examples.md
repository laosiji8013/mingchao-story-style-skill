# 原创示例

以下内容均为新写示例，不是书籍摘录。

## 示例一：解释上下文窗口

输入事实：上下文窗口表示模型一次可以考虑的材料范围，不等于永久记忆。

输出：

```text
标题：上下文窗口，不是模型的永久记忆

大模型的上下文窗口，最简单的理解，就是它一次能摊开多少材料来看。

这事听起来很技术，其实很像一张桌子。

桌子越大，能放下的资料越多。桌子太小，前面的资料就得先收起来，后面的资料才能放下。

问题也在这里。

很多人以为窗口大，模型就什么都记得。并不是。它只是这一次处理任务时，能同时看到更多材料。

所以，窗口大当然有用。长文档、长对话、复杂任务，都会受益。

不过它不是永久记忆。材料乱、问题不清，桌子再大，也只是把混乱摊得更开。
```

## 示例二：解释流程

输入事实：装备流程包含登记、交接、检查、使用、维护和归还，用于明确责任。

输出：

```text
标题：流程不是多填表，是少出错

装备管理流程最重要的作用，不是让人多走几步，而是让每一步都有人知道自己该负责什么。

新人刚接手装备时，最怕的不是东西多。

最怕的是不知道东西从哪来、交给谁、坏了找谁、什么时候要还。

流程就是把这些问题提前摆清楚。

登记，是为了知道谁领了。交接，是为了知道责任从什么时候转过去。检查，是为了让问题别拖到现场才暴露。

这些听起来都是小事。

然而现场真正出问题的时候，往往就是小事没说清楚。

所以流程不是摆样子。它解决的是责任边界和行动顺序。
```

## 示例三：人物材料

输入事实：某位基层负责人接手一个长期延期项目，资源不足，但通过缩小范围和明确责任完成首期交付。

输出：

```text
标题：他接手的不是项目，是一堆没人愿意签字的问题

他接手项目时，距离原定交付时间已经过去两个月。

表面上看，问题是进度慢。

真正的问题却不是时间，而是范围一直在变，责任一直没人认。每个人都在忙，每件事也都“差一点”，最后自然是什么都差一点。

他没有先喊口号，也没有重新画一张更漂亮的计划表。

他做的第一件事，是砍掉首期不需要的功能。第二件事，是把每个剩余任务写到具体负责人名下。

这两个动作都不复杂，甚至谈不上精彩。

然而项目需要的不是精彩，而是有人做选择、有人承担结果。

三周后，首期终于交付。它不完美，但能用，也让后面的改进有了真正的起点。
```
